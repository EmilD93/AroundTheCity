# Sofia City Quest

Full-stack прототип за градска мисия в центъра на София със самостоятелен и състезателен режим.

## Реализирани функции
- 10 location-based мисии със старт от градина „Кристал“.
- Твърд server-side GPS geofence от **5 метра** за всяка мисия.
- GPS точност: за валидна проверка браузърът трябва да отчете точност до 10 м; при изпращане на отговор се взема **нова** GPS позиция.
- Устойчив server-side таймер (`started_at` е в базата и не се рестартира при затваряне на сайта).
- Подсказка = +5 минути наказание.
- Продължаване след затваряне чрез team token в localStorage + server state.
- Самостоятелен режим и Race режим.
- При Race организаторът стартира всички записани отбори в един и същ server timestamp.
- QR код за присъединяване към състезанието.
- Organizer dashboard с live карта, прогрес, времена и anti-cheat flags. Докато страницата на играта е отворена, браузърът изпраща GPS ping приблизително на 10 секунди; мобилната ОС може да спре tracking-а при затворен/приспиван браузър.
- Live leaderboard.
- Снимка/лого на отбор (JPG/PNG/WEBP до 2 MB), пазена в базата.
- Балансирани route variants за намаляване на следването между отбори.
- Anti-cheat: максимална GPS точност, повторна GPS проверка при отговор, кратка валидност на location verification и flag за физически неправдоподобни GPS скокове.
- SQLite DB: competitions, teams, players, games, mission_events.
- Admin JSON endpoint: `/api/admin?key=...`.

## Локален старт
```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```
Отвори `http://localhost:8000`.

## Състезателен flow
1. Избираш „Състезание“, оставяш кода празен и създаваш първия отбор.
2. Отваря се Organizer dashboard и се генерира QR за останалите отбори.
3. Отборите сканират QR, създават име/играчи/снимка и чакат в lobby.
4. Организаторът натиска „Старт на всички отбори“.
5. Всички таймери получават един и същ `started_at` от сървъра.
6. Organizer dashboard показва последните GPS позиции, прогреса, времето и anti-cheat flags.

## GPS поведение
`GPS_RADIUS_M = 5` в `app/main.py`. Това е строг радиус. Центърът на София има места с GPS multipath между сгради, затова точните координати на всички 10 точки трябва да се потвърдят с физически walkthrough преди публично събитие. Ако конкретен landmark не позволява реално достигане на 5 м от зададената координата, коригирай **координатата**, а не радиуса.

## Docker

```bash
docker build -t sofia-city-quest .
docker run -p 8000:8000 -e ADMIN_KEY='strong-secret' -v questdata:/data sofia-city-quest
```

## Vercel + Supabase
Текущата локална версия използва SQLite и е удобна за разработка. За Vercel production deployment базата трябва да се премести към Supabase/PostgreSQL, а снимките могат да се преместят към Supabase Storage. Не са добавени плащания или други платени product features.

## Преди реално събитие
- Направи физически walkthrough на 10-те точки с поне 2 различни телефона.
- Потвърди, че всяка зададена координата попада до 5 м от място, на което участник реално може да застане.
- Провери надписите/табелите на мисии 7 и 10.
- Използвай HTTPS, защото мобилните браузъри изискват secure context за геолокация.
- Смени `ADMIN_KEY`.
